# 설계 결정

## 익숙한 선호를 하나의 체계로

| 사용자가 좋아한 포인트 | naria 적용 |
| --- | --- |
| Apple/IBM 버튼 | 중립색의 주 행동, 한 화면의 명확한 위계, 120ms 눌림, 36/44/52 크기 |
| IBM 타이포 | 공식 IBM Plex Sans KR 400/600, 제목·본문·보조 텍스트의 일관된 스케일 |
| Toss/Adobe 입력 | 위쪽 라벨, 도움말·오류 연결, 필수 표시, 16px 입력, 오류 후 값 유지 |
| Apple 선택 | 일관된 체크·라디오·스위치, 세그먼트 선택 배경의 이동 |
| Toss/Apple 내비게이션 | 단순한 현재 위치 표현, 라벨 있는 하단 탐색, 화면별 Drawer 조합 |
| 카드의 정보 위계 | 제목·설명·본문·하단 행동 구분, Outline/Filled/Elevated 세 역할 |
| Apple/Microsoft 피드백 | 인라인 상태, 토스트, 결과 화면의 목적 분리 |
| IBM 오류 | 원인과 수정 방법을 연결하고 네이티브 입력·포커스·명시적인 메시지 유지 |
| Vercel/당근 모션 | 빠른 조작 반응, 선택 연속성, 결과 확인, 모션 감소에서도 동등한 결과 |
| 공식 아이콘·보라색 제외 | Radix 공식 패키지, 중립색 기반과 교체 가능한 teal 강조색 |

원본 모션 82개를 그대로 제품 UI에 모두 합치지 않았습니다. 비교 갤러리를 보존하고, 제품에는 눌림·선택·펼침·진입·피드백·의도 확인의 6가지 규칙으로 정리했습니다. 글자 해독을 방해하는 반복 효과나 과장된 젤리 변형은 공통 UI의 기본 동작에 넣지 않았습니다.

## 원본과 변경 흐름

`tokens.json → tokens.css`, `컴포넌트 export + 실제 데모 → API/예제 문서`가 생성 방향입니다. 스타일과 동작의 원본은 packages/ui, 설명과 조합은 src/system입니다. 생성 파일을 직접 수정하지 않습니다.

이번 버전은 사용자가 선택한 웹 문서·코드 중심 결과물입니다. TDS 예시는 문서화 범위와 완성도를 이해하는 기준이며, 특정 Figma 파일을 직접 분석하거나 복제한 결과가 아닙니다.

브레이크포인트는 naria의 0/600/900/1200/1600px입니다. 모바일·태블릿·넓은 화면에서 콘텐츠에 맞춰 적응합니다. 반응형은 단순 축소 대신 표→카드, 다이얼로그→시트, 다열→한 열, 메뉴→드로어의 화면 조합으로 정의합니다.

## 제품 적용 경계

일반 웹·모바일웹 UI, 화면 패턴, 상태·키보드·반응형·모션 계약을 제공합니다. 산업별 모든 기능을 한 패키지에 넣지는 않습니다. 지도·전문 차트·리치 텍스트·가상화 그리드는 별도 라이브러리와 조합하며, API·권한·인증·실제 결제는 서비스 계층이 소유합니다.
